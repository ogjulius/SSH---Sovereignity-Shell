# Development

## Setup

```sh
git clone https://github.com/ogjulius/SSH---Sovereignity-Shell.git
cd SSH---Sovereignity-Shell
./bin/ssh-shell                      # run from the checkout (live-reloads on save)
```

Quickshell reloads QML when files change. To test without disturbing your
running setup:

```sh
SSH_SHELL_NO_NOTIFICATIONS=1 \       # don't compete for the notification bus name
SSH_SHELL_CONFIG=/tmp/ssh-dev.json \ # use a throwaway config
qs -p src
```

Drive it with IPC from another terminal: `qs -p src ipc show`,
`qs -p src ipc call lens toggle`, `qs -p src ipc call shell status`.

To test notifications without touching your real daemon, run SSH on a private
session bus: `dbus-run-session -- sh -c 'qs -p src & sleep 2; notify-send hi'`.

## Checks

```sh
make test        # = scripts/test.sh
```

1. **Unit tests** (`src/dev-tests.qml`, run in Quickshell's own JS engine):
   schema validation, fuzzy matching, Atlas model, formatting, palette contrast,
   glyph syntax, keybind generation, Lens intents.
2. **qmllint (Qt 6)** for syntax. Many advisory warnings are expected because
   `qs.*` modules are generated by Quickshell at runtime. Note: Arch's
   `/usr/bin/qmllint` is the Qt 5 tool; the script finds the Qt 6 one.
3. **Load test:** every surface is instantiated offscreen via `dev-render.qml`;
   any QML `TypeError`/`ReferenceError` fails the run.

## Rendering surfaces without a desktop

```sh
QT_QPA_PLATFORM=offscreen SSH_SHELL_NO_NOTIFICATIONS=1 SSH_SHELL_CONFIG=/tmp/x.json \
SSH_RENDER_OUT=/tmp/renders SSH_RENDER="lens atlas" SSH_RENDER_MODES="dark light" \
qs -p src/dev-render.qml
```

These are renders of SSH's real components with live data, composed over a
neutral backdrop. They are **not screenshots** of a running session: there is
no real wallpaper or windows behind them, icon themes are not configured under
the offscreen platform, and window previews are unavailable. Never present them
as screenshots.

## Conventions

- **Files:** `PascalCase.qml` for types, `camelCase.js` libraries with
  `.pragma library`; one component per file; surfaces split into
  `XContent.qml` (pure) + `X.qml` (window).
- **No hard-coded visuals:** colours, sizes, durations come from `Theme`.
- **No new options without the schema:** add to `configuration/Schema.js`, read
  via `Config.<section>.<key>`, expose in `modules/settings/Pages.js`, document
  in `CONFIGURATION.md`. An option that affects nothing is a bug.
- **Processes:** argv arrays only. Never build a shell command from data.
- **Compositor calls** go through `Compositor`, never directly from modules.
- **Dependency direction:** see `ARCHITECTURE.md`; no cycles.
- Comments explain *why*; keep them short.

## Adding a surface

1. `modules/foo/FooContent.qml` — a `FocusScope` with `implicitWidth/Height`.
2. `modules/foo/Foo.qml` — `SurfaceWindow { name: "foo"; placement: ...; content: Component { FooContent {} } }`.
3. A `LazyLoader { active: Surfaces.loaded.foo === true; Foo {} }` in `shell.qml`.
4. Optional: an IPC function and a render target in `dev-render.qml`.

## Adding a compositor backend

Create `compositors/<name>/Backend.qml` exposing the model and actions listed in
`compositors/Compositor.qml`, add detection to `Compositor.kind`, and document
capabilities in `COMPOSITOR_SUPPORT.md`.
